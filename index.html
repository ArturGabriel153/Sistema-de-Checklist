O Projeto

O que é o Sistema de Checklist?

Uma plataforma completa para gerenciar checklists operacionais entre matriz e filiais, com rastreamento de ocorrências e fluxo de aprovação.

🏗️

Problema Resolvido

Empresas com múltiplas filiais precisam garantir que procedimentos operacionais sejam cumpridos. O sistema digitaliza esse processo com rastreabilidade completa e alertas automáticos.

⚙️

Como Funciona

O Master cria templates e os envia às filiais. O Gerente responde com fotos e observações. O Master analisa, registra ocorrências e conclui o ciclo.

📱

Mobile-First

Interface totalmente responsiva com navegação inferior para mobile, header fixo e suporte a safe-area-inset para iPhones. Funciona em qualquer dispositivo.

🌙

Tema Escuro / Claro

Suporte completo a dark mode via data-theme="dark" com variáveis CSS. Transições suaves de 0.3s em todos os componentes — sem flash de tema.

Funcionalidades

O que o sistema faz

Seis módulos integrados cobrindo todo o ciclo de vida operacional de uma rede de filiais.

Modelos reutilizáveis com itens organizados por setores. Dois tipos: padrão e setorizado — com agrupamento visual e colapso por área.

Resposta do Gerente

Partes interessantes do código

frontend/src/pages/master/Dashboard.jsx

O Dashboard usa gsap.context() para escopar animações ao containerRef. Isso evita vazamento de seletores para fora do componente. O ctx.revert() no cleanup garante que animações pendentes sejam canceladas ao desmontar — padrão correto para GSAP + React.

useEffect(() => {
  if (loading) return;

  // gsap.context() escopa todos os seletores ao containerRef
  // e permite cleanup automático com ctx.revert()
  const ctx = gsap.context(() => {

    // Header: fade simples após carregar dados
    gsap.from('.dash-header', {
      opacity: 0,
      duration: 0.55,
      ease: 'power3.out',
      clearProps: 'opacity',  // ← remove o inline style após animar
    });

    // Cards de stats: stagger de 80ms entre cada card
    gsap.from('.stat-card', {
      opacity: 0,
      stagger: 0.08,
      duration: 0.5,
      ease: 'power3.out',
      delay: 0.1,
      clearProps: 'opacity',
    });

    // Seção de ocorrências: entra depois dos cards
    gsap.from('.occ-section', {
      opacity: 0,
      duration: 0.5,
      ease: 'power2.out',
      delay: 0.25,
      clearProps: 'opacity',
    });

    // Linhas da tabela: stagger mais rápido (40ms)
    // cria sensação de "preenchimento" da tabela
    gsap.from('.table-data-row', {
      opacity: 0,
      stagger: 0.04,
      duration: 0.35,
      ease: 'power2.out',
      delay: 0.5,
      clearProps: 'opacity',
    });

  }, containerRef); // ← escopo ao ref do container

  // Cleanup ao desmontar componente
  return () => ctx.revert();

}, [loading]); // ← só dispara quando os dados terminam de carregar
backend/src/middlewares/auth.js

Middleware JWT enxuto. O token é extraído do header Authorization: Bearer <token>, verificado com a secret via jwt.verify() e o payload decodificado é injetado em req.user. O guard somenteMaster é aplicado em cima do autenticar nas rotas exclusivas de master.

const jwt = require('jsonwebtoken');

// Autentica qualquer rota protegida
function autenticar(req, res, next) {
  const token = req.headers.authorization?.replace('Bearer ', '');
  if (!token) return res.status(401).json({ error: 'Não autorizado' });

  try {
    // jwt.verify() valida assinatura + expiração em uma chamada
    // O payload (id, role, filial_id, nome) fica disponível em req.user
    req.user = jwt.verify(token, process.env.JWT_SECRET);
    next();
  } catch {
    res.status(401).json({ error: 'Token inválido' });
  }
}

// Guard adicional para rotas exclusivas do perfil master
function somenteMaster(req, res, next) {
  if (req.user?.role !== 'master')
    return res.status(403).json({ error: 'Acesso restrito a masters' });
  next();
}

module.exports = { autenticar, somenteMaster };

backend/src/routes/envios.js — GET /dashboard/resumo

O endpoint de dashboard agrega dados de múltiplas tabelas Supabase em uma única resposta. O ponto mais interessante é a detecção de atraso: uma ocorrência é "atrasada" se está em status ativo e o prazo já passou — calculado em JS após buscar tudo.

router.get('/dashboard/resumo', autenticar, somenteMaster, async (req, res) => {
  const { data_inicio, data_fim } = req.query;

  // 1. Carrega filiais ativas, envios do período e todos os problemas
  const { data: filiais } = await supabase
    .from('filiais').select('*').eq('ativa', true).order('nome');

  let q = supabase.from('checklist_envios')
    .select('filial_id, status, created_at');
  if (data_inicio) q = q.gte('created_at', data_inicio);
  if (data_fim)    q = q.lte('created_at', data_fim + 'T23:59:59');
  const { data: envios }    = await q;
  const { data: problemas } = await supabase
    .from('problemas')
    .select('filial_id, status, prazo, checklist_envios(filial_id)');

  const today  = new Date().toISOString().split('T')[0];
  const ATIVOS = ['aberto', 'em_execucao', 'resolvido_gerente'];

  // Ocorrência atrasada = status ativo + prazo anterior a hoje
  const isAtrasado = (p) =>
    ATIVOS.includes(p.status) && p.prazo && p.prazo < today;

  // 2. Agrega por filial em memória (mais rápido que N queries)
  const resumo = filiais.map(f => {
    const ef = envios.filter(e => e.filial_id === f.id);
    const pf = problemas.filter(p =>
      (p.filial_id || p.checklist_envios?.filial_id) === f.id
    );
    return {
      filial:                 f,
      total_envios:           ef.length,
      pendentes:              ef.filter(e => e.status === 'pendente').length,
      respondidos:            ef.filter(e => e.status === 'respondido').length,
      concluidos:             ef.filter(e => e.status === 'concluido').length,
      ocorrencias_atrasadas:  pf.filter(p => isAtrasado(p)).length,
      ocorrencias_concluidas: pf.filter(p => p.status === 'confirmado').length,
    };
  });

  res.json({
    data: resumo,
    // Contagens globais para o alerta do topo do dashboard
    globalAbertos:   problemas.filter(p => p.status !== 'confirmado').length,
    globalAtrasadas: problemas.filter(p => isAtrasado(p)).length,
  });
});
frontend/src/pages/gerente/Responder.jsx — submeter()

A submissão valida em cascata antes de qualquer chamada de rede. Após inserir as respostas, os uploads de fotos são disparados em paralelo com Promise.all() — significativamente mais rápido que sequencial quando há muitos itens com fotos.

const submeter = async () => {
  const itens = envio.itens || [];

  // Validação em cascata — para no primeiro problema encontrado
  const semStatus = itens.filter(i => !respostas[i.id]?.status);
  if (semStatus.length) {
    toast.error(`Responda todos os itens (${semStatus.length} pendente(s))`);
    return;
  }
  const semFoto = itens.filter(i => !arquivos[i.id]?.length);
  if (semFoto.length) {
    toast.error(`Adicione foto em ${semFoto.length} item(ns)`);
    return;
  }
  const semObs = itens.filter(i => !respostas[i.id]?.observacao?.trim());
  if (semObs.length) {
    toast.error(`Observação obrigatória em ${semObs.length} item(ns)`);
    return;
  }

  setSalvando(true);
  try {
    // 1. Envia todas as respostas de uma vez
    //    O backend retorna os IDs inseridos para associar os uploads
    const result = await enviosApi.responder(id, {
      respostas: itens.map(item => ({
        item_id:    item.id,
        status:     respostas[item.id].status,
        observacao: respostas[item.id].observacao,
      }))
    });

    // 2. Monta os uploads de fotos e dispara TODOS em paralelo
    //    Promise.all() é muito mais rápido que await em loop sequencial
    const uploads = [];
    for (const [itemId, files] of Object.entries(arquivos)) {
      if (!files.length) continue;
      const resp = result.respostas.find(r => r.item_id === itemId);
      if (!resp) continue;
      const fd = new FormData();
      files.forEach(f => fd.append('arquivos', f));
      fd.append('referencia_id', resp.id);
      fd.append('tipo_referencia', 'resposta');
      uploads.push(arquivosApi.upload(fd));
    }
    if (uploads.length) await Promise.all(uploads); // ← paralelo!

    toast.success('Checklist respondido com sucesso!');
    navigate('/gerente/checklists');
  } catch (err) {
    toast.error(err.response?.data?.erro || 'Erro ao enviar respostas');
  } finally {
    setSalvando(false);
  }
};
